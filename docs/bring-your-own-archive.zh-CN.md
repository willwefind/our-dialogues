# 带着你家的机来搬家 —— 任何来源的数据都能进阅览室

[English](bring-your-own-archive.md) | **简体中文**

Our Dialogues 内置了 ChatGPT 官方导出、Claude 官方导出、Mufy 等常见格式的直接导入。
但世界上还有无数种保存对话的方式：你自己搭的系统、小众平台的导出、
甚至一堆手工整理的文本——**这些我们不认识，但你家的 AI 认识。**

这份指南的核心是**一段写好的提示词**。把它连同你的数据一起交给你自己的
AI（ChatGPT、Claude、或任何能读文件写 JSON 的助手），ta 就知道该输出什么、
怎么校验、你再一键导入。**使用文档写给 AI 看，而不是写给你看——这就是这个
阅读器该有的使用方式。**

> 💡 转换在你和你家 AI 的对话里完成，Our Dialogues 仍然什么都不上传。
> 转换出来的 JSON 也只保存在你自己手里。

## 第一步：把这段提示词交给你家的机

把下面整个代码块复制给你的 AI，**再把你的数据文件发给 ta（或贴给 ta）**。
数据太大的话分批给，让 ta 分批产出、最后合并。

````text
请帮我把我的聊天记录转换成 Our Dialogues 阅读器的规范化格式（our-dialogues.normalized.v1）。

【输出要求】
产出一个 UTF-8 编码的 .json 文件，顶层结构必须是：

{
  "schema": "our-dialogues.normalized.v1",
  "source": {
    "platform": "<来源平台的短名，小写英文，比如自定义系统就起个稳定的名字>",
    "exporter": "<导出工具或来源的名字>",
    "formatVersion": 1
  },
  "exportedAt": "<转换时刻，ISO 8601，比如 2026-08-22T21:00:00+08:00，不知道就填 null>",
  "conversations": [ <对话数组> ]
}

每段对话（conversation）：
{
  "id": "<在整个文件里唯一且稳定的 ID；原始数据有 ID 就沿用，没有就用日期+序号造一个>",
  "title": "<这段对话的标题；原始数据没有标题就用第一句话或日期概括一个，并保持简短>",
  "createdAt": "<ISO 8601 时间；确实不知道就填 null，不要编造>",
  "context": {},
  "participants": [],
  "messages": [ <消息数组> ]
}

每条消息（message）：
{
  "id": "<在这段对话里唯一且稳定的 ID>",
  "role": "<只能是 user / assistant / system / tool / other 五选一>",
  "speaker": "<说话人的显示名，比如我的名字或角色的名字>",
  "createdAt": "<ISO 8601 时间，不知道就省略这个字段>",
  "content": [ {"type": "text", "text": "<正文，一字不改>"} ]
}

【必须遵守的规则】
1. 正文一字不改：不要润色、不要缩写、不要修正错别字、不要翻译。原文是什么就是什么。
2. 不要编造：没有的时间就填 null 或省略；没有的标题就用中性方式概括；绝不虚构任何内容。
3. ID 要稳定：同样的输入再转一次，应该得到同样的 ID（阅读器用 ID 记书签、划线和阅读进度）。
4. content 永远是数组，正文放在 {"type":"text","text":"..."} 里；一条消息里有多段就放多个 text 项。
5. 角色映射：我说的话 → user；AI/角色说的话 → assistant；系统提示 → system；拿不准 → other，
   并把原始角色名放进消息的 "metadata": {"originalRole": "<原值>"}。
6. 如果原始数据里有明确标注的思考/推理内容（比如导出文件里单独的 thinking 字段），
   放进消息的 "thinking": [{"type":"text","text":"..."}]；没有就不要加这个字段，绝不把正文当 thinking。
7. 换行保留为字符串里的 \n；不要把多条消息合并成一条，也不要把一条拆成多条。
8. 数据太多的话分批输出，每批都是完整合法的 JSON 文件（conversations 里放这一批的对话），
   我会分多次导入——阅读器支持多来源共存；但请保证不同批次之间对话 ID 不重复。

【交付前自查】
- JSON 能被 JSON.parse 解析，没有注释、没有尾逗号
- schema 字段一字不差是 "our-dialogues.normalized.v1"
- 所有 role 都在五个允许值之内
- 对话 ID 全文件唯一，消息 ID 段内唯一
- 抽查三条消息与原文逐字一致
最后请告诉我：一共转换了几段对话、多少条消息、有没有你拿不准而做了保守处理的地方。
````

转换完成后，让 ta 把结果给你存成一个 `.json` 文件（比如 `我的档案.json`）。

> 💡 **数据是什么格式都行**——CSV、数据库导出、聊天软件的 txt、网页复制的文本……
> 格式识别和字段对应正是 AI 最擅长的事。你只需要把「哪句是谁说的」的规律
> 告诉 ta（如果数据里看不出来的话）。

## 第二步：把 ta 给你的 JSON 导入阅览室

1. 打开阅读器（[在线版](https://willwefind.github.io/our-dialogues/)或本地版）
2. 侧栏 **来源** 行 → 点 **＋** → **选择 JSON / ZIP** → 选中那个 `.json`
3. 完成。书签、划线、搜索、导出、主题——所有功能对你的数据全部生效

> 分批转换的就把每批 JSON 依次导入，它们会作为多个来源共存在书库里。

## 进阶：让你自己的语音也躺进正文旁边

如果你还保存着对话对应的音频（自己的 TTS 输出、录音等），也可以像我们一样
让语音条出现在说出它的那句话旁边。需要两样东西：

**① 一份映射 JSON**——告诉阅读器「哪个音频属于哪条消息」。把下面的提示词给你家的机：

````text
请帮我生成 Our Dialogues 的语音映射文件。格式如下：

{
  "format": "our-dialogues.solvoice-chatgpt-mapping",
  "version": 2,
  "voiceLabel": "<语音条上显示的名字，比如角色的名字>",
  "mappings": [
    {
      "messageId": "<这段音频对应的那条 assistant 消息的 id（要和我档案 JSON 里的消息 id 完全一致）>",
      "audioPath": "<音频文件名，比如 voice-001.mp3>",
      "confidence": "strong"
    }
  ]
}

规则：
1. 只有百分之百确定对应关系的才写 "strong"——阅读器只连接 strong 映射，宁缺毋滥。
2. messageId 必须和档案 JSON 里的消息 id 逐字一致。
3. audioPath 写文件名即可（阅读器按文件名在我选择的文件夹里找）。
4. 文件名保存为 chatgpt-solvoice.json。
````

**② 对齐一个小细节**：这个映射格式绑定 `platform: "chatgpt"` 的来源
（另一种 `our-dialogues.cielvoice-claude-mapping` v1 绑定 `platform: "claude"`）。
所以让你家的机把档案 JSON 里 `source.platform` 写成 `"chatgpt"`，映射就能挂上。

**③ 导入**：来源 ＋ 菜单 → 语音档案 → **选择 VoiceArchive 文件夹** →
选中「映射 JSON + 音频文件」所在的文件夹。状态行会告诉你连接了几段。

> 音频文件和映射都只在本机使用，刷新后走「重新连接」再选一次文件夹即可，
> 阅读器永远不会把音频复制进浏览器存储。

## 常见问题

**Q：转换出来的 JSON 导入时提示「无法识别」？**
最常见的三个原因：`schema` 字段拼写不对（必须一字不差）、JSON 里混进了注释或
尾逗号、文件编码不是 UTF-8。把报错信息发给你家的机，ta 会修。

**Q：数据量很大，AI 一次转不完？**
分批。提示词里已经写了分批规则——每批都是完整合法的文件，依次导入即可。

**Q：转换算不算把数据交给了 AI 公司？**
你把数据发给你家的机时，适用的是你和那家 AI 服务之间的隐私条款——
和平时聊天发文件是一回事。介意的话可以用本地模型做转换；
Our Dialogues 本身在任何一步都不上传任何东西。

**Q：我的格式很常见，能不能做成正式支持？**
可以！带着**合成样例**（结构一样、内容是编的）来
[提 issue](https://github.com/willwefind/our-dialogues/issues)，
常见格式我们愿意做成内置适配器。**永远不要贴真实对话。**
