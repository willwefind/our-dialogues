# 带着你的旧文字来 —— 日记、梦、微博、信，都能进阅览室

[English](bring-your-personal-archive.md) | **简体中文**

你手里可能有这样一堆字：中学时的纸质日记（后来一页页手打成了 txt）、
坚持了几年的梦境记录、一份微博备份、存在草稿箱里的随笔、没寄出去的信，
还有一些不知道该算什么的碎片。它们不是「对话」，是你一个人写下的——
但同样值得有一间能随时回去的阅览室。

阅读器为这类文字准备了一个专门的来源格式：**私人文字档案**
（`our-dialogues.personal-archive.v1`，完整契约见
[personal-archive-v1.md](personal-archive-v1.md)）。导进来之后，
这些文字就像书一样躺进书库——能翻、能搜、能划线、能存书签，
按「集合」分册，按日期排队，整页展示、没有聊天气泡。

**和姊妹篇的区别一句话讲清**：[聊天搬家指南](bring-your-own-archive.zh-CN.md)
搬的是「你和 AI（或别人）的对话」，一来一往；这一篇搬的是
「你自己写下的文字」——没有对话，只有一位作者。

方法和姊妹篇完全一样：**把下面这段现成提示词，连同你的旧文字，
交给你信任的 AI**；ta 输出规范 JSON；你在阅读器里点两下导入。

> 💡 转换在你自己选择的 AI 里完成，导入在你自己的浏览器里完成。
> Our Dialogues 全程不上传任何东西，也不需要你上传。

| 微博 / 说说 / 短文备份 | ✅ 用这份指南 |

## 第一步：把提示词和你的文字交给你信任的机

把下面整个代码块复制给你的 AI，**再把你的文字发给 ta（或贴给 ta）**。
顺手告诉 ta 三件背景事，ta 会做得更好：

- 这批文字是什么（一本日记？微博备份？一叠信？）；
- 作者名想在阅读器里显示成什么；
- 日期线索藏在哪（本子封面写的年份、文件名里的日期、微博自带的时间戳……）。

````text
请帮我把我的私人文字档案（旧日记、梦境记录、微博式短文、随笔、信件、碎片等）
整理成 Our Dialogues 阅读器的「私人文字档案」格式（our-dialogues.personal-archive.v1）。
这些是档案性质的原文。你的任务是搬运和整理，不是加工。

【输出要求】
产出一个 UTF-8 编码的 .json 文件，结构必须是：

{
  "schema": "our-dialogues.personal-archive.v1",
  "archive": {
    "id": "<这份档案的稳定 ID，小写英文加连字符，比如 banxia-archive；以后重转必须沿用>",
    "name": "<档案显示名，比如：半夏的字纸箱>",
    "author": {
      "id": "<作者稳定 ID，比如 banxia>",
      "name": "<作者显示名，比如：半夏>"
    }
  },
  "exportedAt": "<转换时刻，ISO 8601；不知道就填 null>",
  "collections": [
    {
      "id": "<集合稳定 ID，比如 old-diary>",
      "name": "<集合显示名，比如：纸上日子>",
      "type": "<八选一：diary / dream / essay / microblog / note / letter / fragment / other>",
      "entries": [
        {
          "id": "<条目稳定 ID，规则见下面第 7 条>",
          "title": "<原文自带的标题；没有就填 null>",
          "createdAt": "<ISO 8601；只知道哪一天就写成 2016-03-17；完全不知道就填 null>",
          "updatedAt": "<原文有明确修改时间才填，否则 null>",
          "text": "<正文，一字不改；换行保留为字符串里的 \n>",
          "tags": [],
          "metadata": {}
        }
      ]
    }
  ]
}

一个 collection = 一个本来就存在的整体（一本日记、一份微博备份、一叠信）。
一条 entry = 原文里的一篇 / 一条 / 一封。
数据太多一次做不完就分批转，但最后合并成一个完整的 JSON 文件交给我
（阅读器把一份档案当一个来源）。

【必须遵守的十条规则】
1. 原文一字不改：不润色、不修正错别字、不增删标点、不整理格式。
   哪怕有明显笔误、重复、粗糙的句子，也原样保留——那正是档案的一部分。
2. 绝不改写：不缩写、不概括、不重组段落；不把几条合成一条，也不把一条拆成几条。
3. 绝不翻译：中文是中文，英文是英文，中英混写就保持混写。
4. 不发明日期：知道确切时刻就写完整 ISO 8601（如 2013-08-05T23:47:00+08:00）；
   只知道哪一天就写那一天（如 2016-03-17），整份文件保持同一种写法；
   真的不知道就填 null。绝不推测，绝不编造。
5. 不发明标题：title 只在原文真的自带标题时才填；没有就是 null。
   绝不替原文起文学性的标题——阅读器自己会用日期或首行做显示标题。
6. 保留原有的集合边界：日记是日记、微博是微博、信是信。
   原来是几个本子 / 几个来源，就是几个 collection；不要合并，
   也不要按主题重新分组。类型拿不准就用 other。
7. ID 必须稳定：同一批文字重转一次，必须得到完全相同的 ID。
   优先沿用原始 ID（比如微博自带的数字 ID → weibo-3498273412）；
   没有原始 ID 就用日期加序号（diary-2016-03-17；同一天第二篇 →
   diary-2016-03-17-02）；连日期都没有就用稳定的顺序编号（fragment-0001）。
   绝不使用随机 UUID，也绝不拿标题当 ID。
8. 拿不准就如实报告：一篇从哪里断开、日期归属哪一篇、哪一行算标题——
   凡是解析没把握的地方，宁可多保留、少加工，并在最后逐条告诉我，由我决定。
9. 输出必须是合法的 UTF-8 JSON：能被 JSON.parse 直接解析，
   没有注释、没有尾逗号，schema 字符串一字不差。
10. 这份档案不需要上传到任何地方：转换在这个对话里完成，
    导入由我在自己的浏览器里本地完成，Our Dialogues 不经手数据。
    不要建议我把原文或转换结果上传给任何服务。

【交付前自查】
- JSON 合法：无注释、无尾逗号，编码 UTF-8
- schema 一字不差是 "our-dialogues.personal-archive.v1"
- 每个 type 都在八个允许值之内
- 条目 ID 在整份档案里唯一，且重转可复现
- 抽查三条 text 与原文逐字一致（连错别字和标点一起对）
- 每一个填了 null 的日期和标题，都确认过原文里确实没有
最后请报告：几个集合、共多少条、其中多少条有日期多少条没有，
以及所有你拿不准、做了保守处理的地方。
````

转换完成后，让 ta 把结果给你存成一个 `.json` 文件（比如 `半夏的字纸箱.json`）。

## 转出来长什么样（一个小例子）

下面的例子**全部是编的**，只为看清格式（作者「半夏」是本仓库合成示例里的虚构人物）。

原始材料：一本 2017 年的纸质日记，封面写着年份，正文手打成了 txt——

```text
4月2日 小雨
巷口修鞋的摊子搬走了，留下一块纸牌：修行去了，五月回。
不知道是修鞋的修，还是修行的修。想了一路。
```

转换后的一条 entry：

```json
{
  "id": "diary-2017-04-02",
  "title": null,
  "createdAt": "2017-04-02",
  "updatedAt": null,
  "text": "4月2日 小雨\n巷口修鞋的摊子搬走了，留下一块纸牌：修行去了，五月回。\n不知道是修鞋的修，还是修行的修。想了一路。",
  "tags": [],
  "metadata": {}
}
```

四个值得看的细节：

- **年份 2017 是你告诉 AI 的**（本子封面写的），不是 ta 猜的——这类背景请随文字一起交代；
- **「4月2日 小雨」这行没有从正文里消失**——日期写进 `createdAt`，不等于要动原文；
- **`title` 是 `null`**——原文没有标题就不发明。阅读器会自己用日期当显示标题
  （回退链见[契约](personal-archive-v1.md)）；
- 这一天如果还有第二篇，ID 就是 `diary-2017-04-02-02`。

## 先小样，后大批

十年的字，别一口气全倒进去。**先挑 10–30 篇转一小份**，最好覆盖几种情况：
有日期的、没日期的、带标题的、最长的一篇、格式最乱的一篇。

小样导入后（导入方法见下一节），对照原文检查三件事：

1. **保真**——抽几篇逐字对：错别字还在不在？标点动没动？段落齐不齐？
2. **日期**——有日期的排对位置了吗？没日期的是不是老老实实待在「日期未知」里，
   而不是被编了一个？
3. **标题**——显示的标题是原有标题、日期或首行吗？只要发现 AI 发明的文学标题，打回重转。

发现问题就把具体例子发回给你的 AI 修，重转小样再查一遍。

全部确认后再转全量。两个要点：

- **沿用同一个 `archive.id`、同样的 ID 规则**——这样全量转出来的 ID 和小样完全一致；
- 导入全量文件前，先把小样来源移除（来源行的「移除此来源」），再选全量文件。
  因为 ID 稳定，你在小样上做的书签、划线会落回同样的位置。

## 第二步：导入阅览室

1. 打开阅读器（[在线版](https://willwefind.github.io/our-dialogues/)或本地版）
2. 侧栏 **来源** 行 → 点 **＋** → **选择 JSON / ZIP** → 选中那个 `.json`
3. 完成。状态行会告诉你导入了几个集合、多少篇。书签、划线、搜索、导出、
   主题——所有功能对这些文字全部生效；条目按整页文档展示，页眉是集合名和作者。

## 隐私提醒

- **转换用哪个 AI，你自己选。** 可以是你平时用惯的助手，也可以是跑在自己电脑上的
  本地模型——**真正私密的档案，本地模型是最稳的选择**。
- **真档案别发给你不信任的服务。** 发出去之前想一想：这些字出现在那家服务器上，
  你介意吗？介意就换本地模型，或者只发你不介意的那部分。
- **阅读器这一侧永远本地。** 不管在线版还是本地版，文件都只在你自己的浏览器里解析，
  不上传、不注册、不联网同步。在线版只是「网页本身」放在 GitHub 上。
- 想在 issue 或社区里贴样例时，永远用**合成内容**（结构一样、内容编造），
  别贴真文字。本仓库自己的示例也全部是合成的。

## 常见问题

**Q：同一天写了两篇怎么办？**
ID 加序号：`diary-2016-03-17`、`diary-2016-03-17-02`。先后顺序拿不准，就按原文里的出现顺序。

**Q：很多篇完全不知道日期怎么办？**
老老实实填 `null`。阅读器会把它们归进「日期未知」一组，永远不会替你编一个。
以后考证出来了，改 JSON 重新导入即可——记得 ID 别变。

**Q：中英混写怎么办？**
原样保留。「绝不翻译」是十条规则之一——混写本身就是档案的一部分。

**Q：原文里夹着图片、表情怎么办？**
这个格式只收文字。导出数据里自带的占位符（比如 `[图片]`）原样保留；
**不要**让 AI 看图写话、把描述补进正文。图片本身继续躺在你的硬盘里就好。

**Q：导入时提示「无法识别」？**
三个老原因：`schema` 字符串拼错（必须一字不差）、JSON 里混进了注释或尾逗号、
编码不是 UTF-8。把报错信息发回给你的 AI，ta 会修。
